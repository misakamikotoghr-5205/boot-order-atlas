# Contract and Python API

The JSON contract is an Atlas-specific declaration of review assumptions. It is not an official QNX format. All keys below are required; unknown keys are rejected.

```json
{
  "schema": "boot-order-atlas.contract/v1",
  "initial_resources": [],
  "services": [
    {
      "id": "terminal",
      "argv_prefix": ["terminal-driver", "--port", "1"],
      "provides": ["/dev/terminal1"],
      "requires": [],
      "foreground": "blocks"
    }
  ]
}
```

- IDs are unique simple identifiers. Prefix tokens are literal and case sensitive, including an executable's path when written in source. No basename guessing or longest-prefix priority is applied: overlapping matches are ambiguous.
- Paths are literal normalized absolute POSIX paths. No host file is opened to check them. Declare external/bootstrap-provided resources under `initial_resources` only when justified by the target design.
- `provides` describes resources the service is expected to expose; launch order does not prove this expectation.
- `requires` describes resources required **before launch**. A dependency that a process waits for internally needs a different declaration rather than pretending the process cannot start.
- `foreground`: `blocks` declares that this invocation does not return, `returns` declares it returns, `unknown` leaves that behavior unproven. It is ignored as a blocker when this invocation uses `&`.

```python
from boot_order_atlas import analyze_text, compare_reports, load_contract
from boot_order_atlas.report import render_html

model = load_contract(contract_json_text)
before = analyze_text(before_text, model, "before.build")
after = analyze_text(after_text, model, "after.build")
delta = compare_reports(before, after)
html = render_html(delta)
```

`analyze_text` and `load_contract` raise `ValueError` for unsupported input structures or size limits. They do not mutate the supplied contract. `compare_reports` expects two report objects generated by this version, not arbitrary imported JSON; the CLI only compares source inputs. Returned dictionaries are JSON serializable. Direct Python callers are responsible for handling their filesystem/UI errors.

Reports use `boot-order-atlas.report/v1`. Important fields:

| Field | Meaning |
| --- | --- |
| `source` | Display basename, SHA-256, byte length, original source lines |
| `contract`, `contract_sha256` | Normalized assumptions and canonical fingerprint |
| `scope` | Explicit `target_executed=false`, `sdk_used=false`, no image/readiness validation |
| `events` | Source line, script, kind, argv, modifiers, background flag, matched service and reachability |
| `events[].requirements` | Literal resource, conditional/unproven/declared-initial status and guard line |
| `diagnostics` | Code, level, line or contract scope, message and relevant service/resource IDs |
| `dependency_edges`, `contract_cycles` | Declared resource relationships, not a measured runtime trace |
| `summary` | Review counts and `review_required` / `modeled_with_caveats` |

Comparisons use `boot-order-atlas.comparison/v1`: complete `before`/`after` reports, `contract_changed`, ordered `event_changes`, `line_moves`, diagnostic additions/removals with multiplicity, and `source_diff`. Whitespace/comment-only movement can be reported separately from event changes. Unsupported source is not granted a semantic interpretation.
